## Model and boundaries
Closed Map-backed simulator, no real host or filesystem persistence. Simulated clients share retained host state on reconnect; not evidence of actual crash durability or process restart. Trusted receipt admission, immutable object creation, root CAS and exclusive legacy fence are idealized atomic assumptions; source equality and token are checked, no real multi-key guarantee. Journal retains full synthetic plan/source in memory and is not constrained by the hypothetical single-value limit; real durable receipt format, authentication, privacy, retention, size and cross-device exclusion are unresolved. Root digest is trusted only inside the simulator. No production boot/repository integration.

## State protocol
STAGING -> READY after complete exact readback -> ARMED (intent recorded) -> ATTEMPTED (one attempt) -> CONFIRMED only after complete target recovery. Pre-arm explicit abort retains all objects. Pre-arm restart can explicitly continue staging same receipt, no new operation while pending. After arm, recovery is read-only: old root gives UNCERTAIN, exact complete target gives COMMITTED, corrupt target or divergence blocks. No recovery-triggered retry, rollback or deletion. An armed but not attempted operation is not automatically resumed. Old root remains readable during staging; missing committed target stops, not silent fallback. Source untouched. Model uses 16 KiB value cap, not real APS limit. No garbage collection, encryption or actual persistent journal implemented.
