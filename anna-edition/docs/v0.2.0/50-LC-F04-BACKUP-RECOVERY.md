# LC-F04 — Recovery-capable local backup candidate (r15)
Parent: Phase 09-U6-R6 / 09-U6-R7. Source baseline: 4b942ad01e48e3dd580854f48cd9393e51de29b5. Owner requested implementation; no deployment or live-write authorization.

- Existing v1 remains readable and exportable. v2 uses a random 256-bit DEK, AES-256-GCM with 128-bit tags and fresh 96-bit IVs, independent password and recovery wrapping slots. Password PBKDF2-SHA256 600000 iterations; recovery secret 32 random bytes, HKDF-SHA256 with separate salt and domain separation. Payload AAD binds both slots and fixed header, so tampering with either slot rejects either unlock path. Strict envelope sizes, field allowlists, domain validation and 32 KiB workspace limit.
- Recovery key is a bearer secret; store separately from backup. UI requires re-entry of generated key before export, self-checks both paths before exposing ciphertext, permits explicit key download, password generation and visibility toggle, and local re-encryption with a fresh key. No persistence of credentials, no automatic copy, no runtime mutation API, no network, no model calls. JS strings cannot be guaranteed erased from memory; clearing fields and byte buffers is best effort.
- Recovery/rotation makes a new file, not revocation of old copies. Old v1 requires original password, or fresh export from accessible workspace. Both credentials lost with no source data means unrecoverable. Device key storage, cloud escrow and live restore excluded.
- Preserve r14 private draft and BASELINE_REGRESSED minimum revision 4; LC-F02 remains OPEN/P0. LC-F03 Host retest remains pending. Production gates blocked. CI and real Host acceptance required before deployment/closure. Tests synthetic only.

## R9 review hardening

Unique random 128-bit filename pair token associates each plaintext key download with its new encrypted file; it is a naming aid, not authenticated metadata. Re-download intentionally preserves the same name. Explicit warning: downloaded key is plaintext and must be stored separately, never beside backup. Re-entry confirms correct transcription, not durable custody.
